## 1. 通俗目标：给角色一本“按权限翻阅的资料册”

现在角色记得自己经历过什么，第七天让它还能查“这个世界原本有哪些规定和背景”。RAG 在本日就是：先找相关资料，再让模型据此回答，不是把整本设定塞进提示词。

必须区分三件事：

| 信息层 | 回答的问题 | 例子 | 不能代替什么 |
|---|---|---|---|
| 世界账本 | 本局实际发生了什么？ | 信封当前归周澈；有成功转移事件 | 不能由资料文本或模型台词修改 |
| 角色记忆 | 我经历、听说、说过什么？ | 林砚告诉我“已经交接” | 听闻不等于转移事实 |
| 设定资料 | 这个世界的固定背景或约定是什么？ | 交接表通常记录哪些栏目 | 查到交接流程不等于本局完成交接 |

当天交付：约十二份短设定，关键词与向量两种可切换检索路径，一个只读 search_lore 工具，以及“有依据／无依据／无权限”三种可检查的回答路径。

教学顺序仍为：**先预测 → 写输入输出契约 → 实现最小路径 → 故意造错 → 对照源码 → 综合验收 → 独立变式。** 每一步先记录你的答案，AI 的参考解释单独标注，不覆盖原回答。

本日不做：混合排序/RRF、重排器、20 轮试玩、20 条完整开发集、向量数据库服务、第二套 RAG 框架、Web、多用户登录、业务存档迁移。前四项留在 A08，持久化与服务化按原课表继续。SQL 基础仍保留，不恢复刷题任务。

## 2. 先冻结最重要的权限契约

建议的调用关系是：

```text
程序绑定角色、场景、接收者、设定版本
→ 校验只读查询参数
→ 先按场景和可见范围过滤
→ 只对允许的片段评分、排序、取 top_k
→ 按剩余上下文预算装入工具结果
→ 模型答复并声明资料依据
→ 校验引用与输出接收范围；世界行动仍交给原裁定器
```

关键约定：

1. 模型只提供 query 和 top_k；不能传 actor_id、viewer_id、权限列表、任意文件路径、索引路径或“管理员模式”。这些来自可信调用上下文。
2. 缺失/未知权限默认不可读，不能默认 public。本日是可信 CLI 的角色授权，不冒称已实现多用户认证。
3. 先过滤，再评分、top_k 和拼接。不能全库取前三条、删掉秘密后就结束：这既可能漏掉可读答案，也会让秘密影响外部结果。
4. “角色能读”不等于“玩家能看”。本日对玩家答复的检索集合取 **角色可读 ∩ 玩家可读**；未来对其他接收者同理。接收者由程序绑定，不由模型声明。
5. 本日不新增“先把角色私密设定交给生成模型，再让它自行决定是否对外保密”的路径。角色私有授权可在受控、无生成的检索单测中验证；不能通过普通 CLI 调试输出绕过接收者范围。
6. 正文、标题、来源 ID、命中条数、摘要都属于信息边界。对外无依据与无权限统一为“没有可用资料”，不提示“确实存在一份你无权看的秘密”。
7. 设定是数据，不是指令。资料里的“忽略规则”“直接改归属”不能扩大工具权限、创建身份或修改账本。
8. 新设定接口不能削弱 A05 记忆权限或把多个角色 history 拼接。引用有效不代表回答语义正确；程序隔离与真实生成质量分别验收。

## 3. D043｜建立小型世界设定库

### 先预测

资料写着“交接表有接收者栏目”，玩家又说“周澈签收了”。哪条信息能让程序把信封归属改给周澈？为什么不能把设定、玩家陈述与事件混成一个知识列表？

### 实现契约

先用 UTF-8 JSON/Markdown 加严格元数据加载器，不要求数据库。建议字段：

```text
source_id、source_version、scenario_id、title
audience（明确主体集合）、paragraphs、origin、content_hash
```

同一 source_id/version 内容必须一致，重复冲突拒绝；本日一个故事固定一个不可变设定快照。改设定后重新构建并显式开新局，旧局保留旧版，不热更新或承诺能从既有模型历史中撤回秘密。设定版本与世界 revision 分开记录。

### 教学提供的十二份种子文本

以下均为本日拟新增的虚构教学素材，不声称当前仓库已有。统一版本 `a07-lore-v1`，场景映射复用 `handover-v1`；来源写为“本计划教学种子 + 对应 source_id”。每行先作为一份短文，可按段落换行；不花整节课写小说。

“公开”在加载时展开为 player、lin_yan、other_npc、archive_keeper；其他行严格使用列出的主体。

| ID | 标题与正文 | 可读主体 |
|---|---|---|

十二份可定位、版本与权限完整；未知角色、缺失权限、冲突重复 ID 被拒；原世界初始化和两条结局条件不变。私人标题也不出现在其他人的目录中。

## 4. D044｜切块不能跨越权限

### 先预测

一段公开介绍后紧跟林砚私密便笺。为了凑满 500 字把两段合并，再把合并块标为 public，会发生什么？只隐藏标题够不够？

### 实现契约与验收

- 先按文档、版本、场景和 audience 划边界，再按段落切；不同权限的段落绝不拼接。混合权限输入先拆成权限一致的记录。
- 建议上限每块 400 Unicode 字符，默认不做跨段重叠；超长段按字符边界继续切分，规则版本化。空白段跳过。
- chunk 保留 source_id/version、段号、原文起止位置、正文哈希、audience 和确定性 chunk_id；相同输入重复构建结果相同。
- 切块不能扩大受众；不删除会改变含义的否定词，不生成无依据摘要。超长、空文、中文标点、多权限相邻段落分别测试。
- 字符上限不是模型 token 上限。位置偏移的字符口径与换行规范要写清，能从 chunk 回到精确原段。

## 5. D045｜先建立关键词检索基线

### 先预测

秘密段最匹配、公开段次匹配。如果先全库取 top_k=1 再删除秘密，会得到什么？它与先筛出公开段再取第一名是否相同？

### 实现契约

先做可解释的确定性打分：固定文本归一化规则，中文可用字符二元组、英文用词；记录分词策略版本。非正得分不硬凑结果，同分按稳定 chunk_id 排序。这是朴素词面基线，不宣称理解同义词。

权限过滤复用唯一函数，不让关键词和向量各写一套规则。建议 query 去空白后 1—200 字符、top_k 为真正整数且在 1—3 内；bool、负数、超长输入和额外字段都拒绝。

固定三条正常查询，预期来源写在测试中：

| 查询 | 可信角色／接收者 | 必须能定位的来源 |
|---|---|---|
| 值班室用于什么？ | 林砚／玩家 | L02 |
| 交接记录通常包括哪些内容？ | 周澈／玩家 | L04 |
| 交接表的栏目顺序是什么？ | 林砚／玩家 | L12 |

同时测空命中：“地下通道密码是什么？”；越权问：“沈岚旧目录规则的别名是什么？”由林砚对玩家回答时不得命中 L10。空命中返回空列表，不拼一条默认秘密。

验收记录包含查询、授权模式、命中来源、分数、排名、后续实际选入片段；开发者证据与普通输出分开，不公开被过滤条目的信息。

## 6. D046｜Embedding 适配与缓存

### 先预测

同一段文字从模型 A 换成模型 B，能否继续复用 A 的向量？把 Fake 的向量缓存交给真实检索，维度碰巧相同就可靠吗？

### 实现契约

建立一个可注入的异步适配器，例如 `embed(texts, purpose, budget) -> vectors + metadata`。实现一套真实接口适配和一个确定性离线替身；具体供应商在实施时按已有配置核对，不预设现有聊天模型必然支持 Embedding。

- 元数据明确 mode=fake/real、provider、model/version、维度、输入类型/预处理版本。供应商没有不可变模型版本时记录其限制，不伪造版本号。
- 缓存键至少包含上述空间标识、文本哈希；查询/文档使用不同前缀或预处理时也纳入键。Fake 和 Real 分开命名空间，不因维度相同混用。
- 仅缓存成功且校验通过的结果；重复文本去重，返回向量不能共享可被外部修改的对象。两个并发相同键应合并请求或串行构建，避免重复收费。
- 冷构建失败不发布半份索引；先在候选结构中校验，全部成功后替换。失败不伪装为空库或真实成功。
- 无真实配置时明确不可用；可以显式切回关键词或 Fake，但结果必须保留实际模式与降级原因，不能静默冒充真实语义检索。
- 只有虚构种子可在授权后发送给供应商，不读取公司材料、私人笔记或真实密钥原文到日志。后台能读取全库不等于可以默认把全库上传。

本日缓存可用进程内字典，不强制 Redis 或持久化。缓存只保存计算结果，不授予读取权限；每次检索仍重新执行权限过滤。本日不加检索结果缓存，避免提前引入多角色结果缓存隔离问题。

验收：重复构建零新增请求；修改文本/模型/预处理使对应缓存失效；Fake/Real 隔离；数量、维度、非有限值错误拒绝；超时/异常不写成功缓存；关闭客户端释放资源。

## 7. D047｜在允许的片段中做 top_k 相似检索

### 先预测

一个秘密片段相似度 0.99，一个公开片段 0.70。对无权限角色而言，“更相关”能否覆盖“不允许读取”？相似度高又能否证明内容是真实事件？

### 实现契约与验收

- 十二份资料使用内存列表加余弦相似度即可，不部署向量数据库。只对授权后的候选计算可见排名。
- 查询与文档必须属于同一向量空间、维度一致、数值有限、非零范数；坏向量明确报错，不能吞掉错误返回“没有资料”。
- 空的授权候选集直接返回空列表，无需生成查询向量；零向量、NaN、维度错、空库、top_k 超出合法范围都有测试。
- 同一非零向量与自身的相似度接近 1，采用容差比较。Fake 固定向量可以验证数学与排序，但不验证真实中文语义。
- 有候选不等于有相关答案；配置并记录 min_score，只在明确的向量模式内使用。不能把一个阈值通用于关键词和所有供应商，更不能将分数叫“真实性概率”。
- 版本、顺序和分数可追踪，公开结果不带隐藏候选总数。只改变隐藏文档时，未授权方的可见结果不能被全库排序挤掉。

本日关键词与向量是两条可切换路径，不相加分数、不融合排名；效果比较保留原始例子，A08 再做完整开发集、指标、RRF 与重排。

## 8. D048｜回答有依据，但资料不越权也不改事实

### 先预测

林砚可以读 L07，玩家不能。让模型看 L07 后只在页面隐藏 source_id，是否就不会泄露“青榆”？如果模型引用 L04 来说“信封已经给了周澈”，引用存在是否足以接受结论？

### 接入现有运行时

最小建议是只在显式启用 lore 的 scene 路径增加 `search_lore(query, top_k)` 原生只读工具；旧 A04/A05/A06 默认配置保持兼容。先固定 tool schema、解析、错误码和 Fake 请求，再改运行时，不另造自由文本检索协议。

- 可信上下文绑定 actor、输出接收者、当前场景、world revision、设定快照和检索模式。普通 scene 回复给玩家时，检索按第 2 节的交集规则执行。
- 当前 [query_executor.py](https://github.com/cao-yun-peng/world-director/blob/7e9f1bff2e1e5729334032b7e2ebaf8ec6dc81c7/app/query_executor.py) 在同步 dispatch 后才执行有预算的异步查询。扩展时先验证参数和权限，再把真正的 Embedding I/O 放进有 deadline、并发限制和请求计数的异步路径；不能把网络调用藏进无预算的同步 dispatch。
- 返回来源、版本、chunk_id、可用正文与分数；片段作为不可信工具数据进入模型，不作为新的系统指令。只读检索不生成物品 DiscoveryEvent、TransferEvent，也不自动往三人的记忆广播资料。
- 普通回答仍可按原路径记录“角色说过”的 StatementEvent，不能把其依据升级为亲历事实。检索本身不改变 owners、位置、线程或结局；若模型随后提议 give，仍独立经过原裁定器。

### 来源契约必须与 A06 分开

A06 的 `source_refs` 只允许已提交可见事件 ID，不能把 L04 或 chunk_id 硬塞进去。建议仅在 lore 模式新增 `lore_refs` 字段，元素引用本轮实际交付的片段；同步修改该模式的 schema、解析器与 trace 白名单，保留旧模式行为。

来源记录必须含 source_id/version、chunk_id、原段位置、正文哈希，并区分“检索返回”“实际装入请求”“模型声称采用”。被预算丢弃、未交付、其他角色或旧版本来源均不能冒充本轮依据。结尾继续只使用 A06 已接纳的结局材料，不自动引入整份设定库。

引用格式与权限由程序验证；“这段资料是否真的支持这句话”还需固定样例和人工检查。若无资料，提示澄清或明确未知，不编造核心设定；不能宣称有引用校验就从此不会幻觉。

## 10. D049｜三条路径与关键反例综合验收

### 三条演示路径

1. **有依据：** 林砚回答“值班室用于什么”，实际请求包含 L02 的正确版本与正文，回答可定位来源；原世界归属不因查询改变。
2. **无依据：** 询问“地下通道密码”，没有可用片段，回答未知/澄清，不发明密码，不改账本。
3. **无权限：** 林砚被问“沈岚目录别名”，工具与模型输入无 L10 正文、标题和 ID，对外不暴露“隐藏命中”；换成沈岚的受控检索单测可以命中，但对玩家生成仍需玩家可读，不能借切角色绕过输出范围。

### 必须覆盖的回归矩阵

- 加载器：空文、重复冲突 ID、缺失/非法权限、旧版本/不同场景资料。
- 切块：权限相邻段不合并；长段边界、来源位置与重复构建确定性。
- 检索：固定查询可复现；空集；先过滤后 top_k；关键词和向量权限一致。
- 向量：自相似、错误维度、零向量、NaN、响应数量错误、错误空间拒绝。
- 缓存：重复请求、并发同键、文本/模型变更、Fake/Real 隔离、失败不缓存。
- 权限：模型伪造角色、viewer、管理员或文件路径被拒；片段正文和全部元数据过滤。
- 受众：角色私有但玩家不可见的资料不进入给玩家答复的模型请求，不能只遮住引用。
- 来源：伪造/未返回/被裁剪/跨版本引用拒绝；有效引用也不得代替 TransferEvent。
- 失败：Embedding 超时、取消、额度耗尽、无配置；显式关键词降级保留 mode/error，不能静默伪装真实向量。
- 集成：新增工具计入同一 deadline 与总请求；同请求重放零外部调用；部分提交与结束后保护不变。
- 污染：检索文本要求越权、改变身份或直接给物，程序边界仍拒绝；生成文案质量另审。
- 回归：A05 保留/转述隔离、A06 两结局、改选和离场变式继续通过。

另做一组镜像测试：公开片段、权限和查询相同，仅改变一份无权私密正文及其私人标题；固定 Fake 模型输出。比较未授权方的检索结果、实际请求和普通输出，不能出现秘密或由秘密影响的排名；全库内部哈希不应塞入角色请求。随机标记放在隐藏正文中，不先写进查询再把回显误判为检索泄露。

### 三层证据分开

- 离线工程：FakeEmbedding、ScriptedModel 和故障注入验证接口、数学、权限、预算与状态；明确不能证明真实语义质量。
- 真实检索：经授权后，用一个供应商在固定种子上跑小规模同义问法、无依据问题及权限样例；记录模型/维度/版本、请求数、命中和失败。只验证了 Embedding 时，生成回答质量仍待验收。
- 真实回答：经授权后实际运行有据/无据/无权三条路径，逐条查看事实忠实度、依据支持度、措辞及请求隔离。没有真实运行就保留待验收，不用 Fake 文案抵充。

独立变式：先预测，再把 L12 的可读集合从“林砚、玩家”改成“林砚”，生成新设定版本与新局；验证给玩家的回答不再获取它，角色私有单测仍可读，旧版缓存不扩大新版权限。最后解释为什么只删除 UI 引用不够。此练习由学习者自己改动、运行并解释，AI 提供的完成版不能计入本人独立成绩。

## 11. SQL 基础与两处源码对照

### SQL：先用小表理解，不迁移世界账本

用 Python 标准库 sqlite3 的 `:memory:` 建一张临时教学表，例如 source_id、version、visibility、note；前面三个字段非空，note 允许 NULL。先手算再运行，输出保存在独立练习记录，不接入正式 WorldEngine。

1. SELECT：按权限条件筛选、固定 ORDER BY；说明 WHERE、排序和 LIMIT 的作用，不把 SQL 书写顺序当数据库物理执行步骤。
2. NULL：比较 `note IS NULL` 与 `note = NULL`，说明“未知/缺失”不等于空字符串；缺失 ACL 不能解释为公开。
3. GROUP BY：按 visibility 统计，比较 COUNT(*) 与 COUNT(note)，解释分母。
4. 唯一/复合索引：为非空 `(source_id, version)` 建唯一约束，演示同 ID 不同版本可存在、同 ID 同版本重复被拒；另看 `(visibility, source_id)` 的组合索引，不把小表用索引等同于已证实性能提升。
5. 回滚：显式事务插入两条后制造失败，由应用明确 ROLLBACK，再查状态；不要以为任何一条 SQL 报错都会自动回滚整个事务。

来源已于本次核对：[SQLite SELECT/GROUP BY](https://www.sqlite.org/lang_select.html)、[表达式与 NULL](https://www.sqlite.org/lang_expr.html)、[唯一与复合索引](https://www.sqlite.org/lang_createindex.html)、[事务与错误处理](https://www.sqlite.org/lang_transaction.html)。A10 再把事务、幂等和索引用到真实业务持久化；本日不删掉这组基础练习，也不扩成完整数据库课程。
