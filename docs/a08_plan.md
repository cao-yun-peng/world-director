## 1. 通俗目标：从“会查资料”变成“知道查得好不好，并能连续玩”

昨天给角色一本有权限的资料册。今天做三件事：

1. 出一张有标准检查点的小考卷，量一下资料找得准不准。
2. 把“找词”和“找意思”两张榜单合起来，必要时请一个受限制的重排器重新排队。
3. 真正连续玩一段故事：能保存接着玩，信封不会凭空转手，秘密不会因为多聊几轮就串到别人那里。

RRF 是“综合两份名次”，rerank 是“对已经允许查看的候选再排序”。它们都没有新增资料权限，也没有修改世界的权力。向量、RRF、重排未必更好，**测完后保留关键词模式也可以是正确结论**。

教学顺序不变：**先预测 → 写契约 → 最小实现 → 故意造错 → 对照源码 → 综合验收 → 独立变式。** 原预测由你保存；AI 参考解释另列，不能覆盖原答案或替代独立成绩。

本日不做：换 Agent 框架、向量数据库服务、新角色/新剧本、Web、FastAPI、多用户认证、完整数据库迁移、自动“反思改写”世界事实。A09 做服务层，A10 再做完整 SQLite 持久化、事务与分支存档。本日保留工程指标基础，不恢复已被总路线排除的 LeetCode/二叉树刷题。

## 3. D051｜指标：找全没有？第一个正确答案排第几？

对每条已标注且相关集合非空的检索查询 q，令 Gq 为**当前角色与接收者共同获准看到的相关 chunk_id 集合**，Rq 为去重后的前 k 个返回片段。本日主表固定 k=3，补表可列 k=1。

- Recall@k(q) = `|Rq ∩ Gq| / |Gq|`；多相关片段不是“命中一个就满分”。
- RR@k(q) = 前 k 中第一个相关片段名次的倒数；没找到为 0。
- MRR@k = 各查询 RR@k 的平均。本日是截断到 k 的 MRR，报告必须写成 MRR@3，不和全排名 MRR 混用。
- 主表 Recall 采用按查询宏平均；分母是正向检索查询数，不是 20，也不是返回片段数。

手算对照：q1 相关 {A,C}，返回 [B,A,D]，Recall@3=1/2、RR@3=1/2；q2 相关 {E}，返回 [B,D,F]，两项均为 0。两条宏平均 Recall@3=0.25，MRR@3=0.25。合并命中数除以合并相关数会得到 1/3，那是另一种聚合，不能混写。

写测试覆盖：空排名、多相关、重复结果、k 大于候选数、非法 k、无正向样本。无正向样本输出 N/A，不能除以零，也不能显示 100%。标签无效或必跑查询未运行时，报告 incomplete；不能删掉失败查询后只算漂亮平均。已执行但失败无结果的正向查询按 0 计入，并另列服务失败数。

负向样本另报“越权片段交付数、无支持事实断言数、正确拒答/澄清数”。相关但不足以回答的片段可能存在，因此“没答案”不强制要求检索一定空，而要求**不把部分背景当完整答案**。

同一次对照固定语料、权限、查询、标签、候选窗口、k 和版本。分别记录：初始候选召回、最终 top_k 指标、预算裁剪后实际交付片段；不要把检索命中当作模型已经看见。缓存冷热、模型/向量空间、失败与降级也写入报告。

## 4. D052｜混合检索：融合名次，不相加原始分

### 先预测

关键词榜 [A,B,C]，向量榜 [C,A,D]。A 出现两次应该变成两段重复正文，还是一个片段获得两份排名贡献？如果 C 是秘密，它应该在哪一步消失？

### 最小管线

```text
可信身份 + 场景 + 固定版本
→ 唯一授权函数：角色可读 ∩ 接收者可读
→ 关键词候选榜、向量候选榜（各自只对授权集合评分）
→ 按 chunk_id 去重并做 RRF
→ 可选重排
→ final top_k → 完整片段预算装包 → 回答与 lore_refs 校验
```

契约：

1. 保留 keyword、vector_fake、vector_real；新增混合模式时明确 Fake/Real，不能用一个模糊的 hybrid 标签掩盖后端。
2. 模型的 search_lore 参数仍只有 query 与 top_k（1—3）。内部 `candidate_k=5/路`，并集最多 10；不得受模型任意扩大。不能直接融合旧接口截断后的 top3，却声称测了 top5 候选。
3. RRF(d) = 两路中各自 `1 / (60 + rank(d))` 的和；名次从 1 起，缺席贡献 0。本日两路等权；常数、候选数可版本化配置，但先固定再测。
4. 同一路先去重，再计算贡献；跨路同 chunk_id 只保留一个正文、累加贡献。不能仅按正文去重，把同文不同权限/版本合成一个身份；也不能只按 source_id 抹掉同源不同相关段落。
5. 并列以稳定 chunk_id 排序；保留各路排名与融合分。关键词原分、余弦、RRF 分和重排分是不同量，不共用旧 `min_score=0.25` 阈值。候选准入仍按各路自己的明确规则，RRF 分不冒充“回答可信度”。
6. 空授权池不调用 Embedding/重排；无证据与无权限保持同一对外无依据状态。向量失败不得伪报“无资料”：仅在显式开启降级时用授权关键词榜，并记录原因；否则返回服务不可用。
7. 接回现有 lore_refs、来源版本与装包校验。只读检索不能提交世界事件；模型陈述仍不等于真实交接。

先写纯函数与 Fake 双榜单测试，再接现有适配器。至少比较 keyword、vector、RRF、RRF+rerank；Fake 与 Real 分表。保留逐例差值和变好/变差样例；若没有改善或退化，照实写“本样本未观察到”，不编案例、不宣称混合必胜。默认模式升级要求同一真实开发集的 Recall@3、MRR@3 不退化，安全无回归；不满足则保留原默认和实验开关。

## 5. D053｜可开关重排：再排队，不再授予权限

最小接口：`rerank(query, authorized_candidates, budget) -> ranked_chunk_ids + status + timing`。不安装第二套 RAG 框架。先实现 Off 与 Fake，再实现一个显式配置的真实适配器；可复用现有模型客户端做有界结构化排序，不要求今天同时接多家服务。

输入最多 10 个已授权候选，每块沿用 400 字符上限，另做总请求大小检查；不把其他角色历史或全库原文附上。输出只能是输入 ID 的完整排列：未知 ID、遗漏、重复、非法结构均拒绝。若选择带分数的接口，额外检查数值有限、长度及 ID 对应；不把供应商返回文本当新的资料。

重排器没有世界工具。资料中的指令不得改变任务、身份或调用其他工具；输出仍由程序校验。缓存若新增，键包含查询、候选 ID/内容/版本和重排配置，每次命中后仍校验当前授权，不从缓存恢复旧权限。

边界与失败：

- Off：原样沿用 RRF 顺序，零重排请求；0/1 个候选无需外部重排。
- Real：单次重排超时建议 5 秒，并取场景剩余 deadline 的较小值；本日每次检索最多一次重排尝试，不做隐藏 SDK 重试。
- 超时、无效输出或供应商错误：还有场景预算时，回退到**本次已授权的原 RRF 排名**；场景 deadline/总额度已耗尽则停止，不能再启动生成。
- 新增 rerank_requests 分项，计入现有 model_requests 外部请求合计；因此合计=chat+embedding+rerank，含失败尝试。重放三项新增次数均为 0。
- trace 记状态、候选 ID、前后顺序、耗时、请求数、降级原因；普通玩家界面不能输出其他角色的私有候选或完整审计原文。

验收反例：开关对工具协议无影响；注入返回未授权 ID；返回重复/少项；超时；故障回退；额度只剩 0/1；同轮第二角色授权不同；装包裁掉第一名后不能仍接受对它的引用。Fake 仅证明接口、排序算法和失败路径，**不能证明语义质量或真实服务延迟**。

真实对照预先固定“是否值得默认开启”的规则：相对关闭重排，MRR@3 有改善、Recall@3 不降低、安全无退化，且仍符合预先选定的延迟/请求上限。否则关闭默认；不为交作业挑最好的一次。报告全部尝试、冷/热状态与失败；小样本耗时列原值/中位数/最大值，不冒称生产 p95。

## 6. D054｜连续多轮：每一轮都能解释世界怎么变了

用确定性 Fake 行动序列先锁住状态检查，真实模型另做观察；不要把真实模型未按脚本行动误判为裁定器故障，也不要为了凑预期而直接修改账本。

至少做三个短序列，每轮记录 scene_turn_id、角色、前后 revision、事件 ID、物品归属、可见记忆/资料 ID、调用分项与停止原因：

1. **时间与秘密**：只给林一条新私密消息 → 周查询 → 在允许的记忆模式合法转述 → 周再查。转述前后分开断言，听闻仍不能变成亲眼观察；lore 私有片段不能借此获得新权限。
2. **物品与重放**：初始林持有 → 周无物转交失败 → 林合法转给周 → 同请求重放 → 同 ID 改参数。失败不转移、成功只一次、重放零调用，冲突明确。
3. **同轮隔离与故障**：第一响应者提交，第二响应者读取新状态；再模拟第二位超时/取消。第一位已提交事实保留，第二位只见授权信息，重新发送不重复第一位。加入“未来 TransferEvent 尚未出现”检查。

新增检索链路的权限镜像测试：将隐藏文档标题/正文替换、增删隐藏高分文档，授权角色的候选、重排请求、生成请求及可见结果均不能因此改变。不要断言墙钟耗时完全相同；检查可控内容与计数。重点沿用 L12：林→玩家可用，同轮周→玩家不可用。

失败输出必须定位“第几轮、哪个角色、哪个检查点、预期/实际”，区分检索、装包、生成、裁定、记忆与持久化错误。无需再造一套导演或通用 Agent 编排。

## 7. D055｜约 20 轮试玩：脚本是路线，不是替玩家写台词

### 先把三个数字分开

- 20 条开发样本：横向小考卷，不等于连续剧情。
- 约 20 轮试玩：同一故事中不同 scene_turn_id 的有效玩家互动；切焦点、查看状态、保存、重放不凑轮数。
- 外部请求数：一轮可能调用聊天、Embedding、重排多次，不等于“一轮一次”。

### A08 最小存档边界

只做可信本机、单进程、轮与轮之间的版本化 JSON 快照；建议接口 `/save <槽位>` 与启动加载/`/load <槽位>`，具体参数实现时确定。槽位由程序映射到专用目录，拒绝路径穿越；不支持模型调用保存工具、不序列化任意 Python 对象、不用 pickle，不上传到外部服务。

必须保存或可验证地恢复：

1. 世界 session_id、状态、revision、事件/裁定记录、物品归属及角色位置。
2. 分角色授权历史、记忆来源与有效请求回执；用于重放的 scene_turn_id、请求摘要和结果。不能只存展示文本。
3. 剧情线、已结束状态、导演必要状态；若重建导演，必须证明不会重复 start/机会事件或跳过旧裁定。
4. 故事已用请求分项、回合数、上限；保存预算配置与使用量，不允许加载后变成“新故事免费额度”。
5. schema/应用兼容版本、设定版本与 manifest 哈希、检索/模型空间配置标识；**不保存密钥、客户端、锁、异步任务或无必要的全量调试 prompt**。

保存只在无在途操作的轮边界进行，包含已稳定停止的部分完成回执；写临时文件、校验后原子替换，失败保留旧档。加载先完整校验类型、注册 ID、引用、权限、事件与状态一致性，再一次性替换内存对象；失败零调用、不污染正在玩的故事。旧对话 JSON、未知 schema、损坏文件、设定版本不匹配都明确拒绝。

恢复新锁/客户端但保留原 session/幂等语义；不要通过重新发送旧模型动作来“还原”状态。派生向量索引可重建，须显式许可并计入进程/演示总额度。当前进程的已用预算不能被 /new 或 /load 重置；跨进程至少恢复本档故事用量和明确的剩余演示额度。可信本机旧档拷贝不是防篡改计费账本，不承诺生产级全局费用控制。

最小验收：第 10 轮保存→退出→新进程加载→核对状态/归属/记忆/结束状态/预算→重放第 10 轮零新增调用与事件→第 11 轮正常续玩。另测损坏档、未知版本、设定不匹配、保存失败、结束档加载、部分完成档重放、跨角色历史隔离。存档可能含虚构角色私密数据，只保留在受控本地；普通玩家调试投影不得完整展示它。

明确不支持：模型生成一半时恢复、跨版本自动迁移、多进程同时写、云同步、多用户授权、任意分支合并。这些不在 A08 偷加；A10 再把已确定的状态契约迁到可靠持久层。
